# Scene

A native macOS app that gives your desktop, terminals, and code editors one theme in one step. It shows every change first and can put your original setup back.

Design and research: [docs/research-and-architecture.md](docs/research-and-architecture.md).

## What the MVP does

| Area | Apps | How |
|---|---|---|
| Desktop | Wallpaper, Light/Dark | `NSWorkspace`; System Events, or the experimental private call |
| Experimental | Accent color, icon & widget style | Private calls in the `scene-tweak` helper, on tested macOS builds only |
| Terminals | Ghostty, iTerm2 | Scene-owned theme files plus one marked include line; iTerm2 Dynamic Profile |
| Editors | VS Code, Cursor, VSCodium, Windsurf, Neovim | Generated theme extension plus a comment-preserving settings edit; Neovim plugin shim plus a JSON data file |

## Theme switcher

Press ⌃⇧⌘Space (Omarchy's Super + Ctrl + Shift + Space) anywhere to show your themes over every screen. ← → choose (or h l, or 1–9), ↑ ↓ switch Light/Dark, ↩ applies with your remembered app choices, Esc closes. Change the shortcut in Settings. The shortcut works while Scene runs; Scene keeps running after you close its window, and Settings has "Open Scene at login".

Every change goes through one engine that records the original value first, journals each step, verifies the result, and can undo it. Restore uses a three-way rule: values Scene wrote go back; values you changed afterwards stay.

## Backgrounds

Each look of a theme (dark or light) has 3 backgrounds. Pick one under the preview on the theme's page; the switcher and Apply use your pick. ⌃⌥⌘Space shows the current theme's next background (Omarchy's Super + Ctrl + Space; ⌃⌘Space is taken by macOS Emoji & Symbols). It changes only the wallpaper, and Undo goes back. Change the shortcut in Settings.

## Settings

Open Settings with ⌘, or the gear in the toolbar. General has login and menu bar options. Shortcuts records, resets, or turns off each global shortcut and lists the switcher's keys. Apps chooses which apps a theme changes. Experimental controls the private macOS calls.

## Build and run

Requirements: macOS 14 or later to run. Xcode 26 or later to build, because an app linked before SDK 26 does not get the macOS 26 design.

```sh
open Scene.xcodeproj          # Scene scheme: ⌘R runs the app, ⌘U runs the SceneKit tests
./Scripts/test.sh             # the same 120 tests from the command line
./Scripts/package_app.sh      # builds build/Scene.app (ad-hoc signed)
open build/Scene.app
```

The scripts use `/Applications/Xcode.app`, never a beta. Some tests use Ghostty, VS Code, and Neovim if they are installed, with isolated profiles only.

To make a distributable build, run `./Scripts/release.sh`. It follows the same steps as FindSFSymbols and Jolt: a universal (arm64 and x86_64) build, Developer ID signing (Techzy LLC, 539293JFA3) with hardened runtime and a secure timestamp, notarization with the `camus-notary` keychain profile, stapling, a Gatekeeper check, and `dist/Scene-<version>.zip`. It publishes nothing. The version lives in `version.env`.

## Verified on macOS 26.6.2 (25G83)

- The live test (`SCENE_LIVE=1 SCENE_LIVE_TWEAKS=1 swift test --package-path Packages/SceneKit --filter SceneLiveTests`, after one Xcode build so the helper exists) applied Catppuccin to the real wallpaper, Ghostty, Neovim, VS Code, Cursor, accent color, and icon style, then restored it. Apply took 0.5–1.3 s. Every watched config file was byte-identical after restore.
- `./Scripts/verify-tweaks.sh` passed 7 of 7 private-call checks (Light/Dark, Auto, accent, three icon styles including a custom tint) and restored every original value. Run it again on each new macOS build before adding the build to `TweakCatalog.testedBuilds`.

Not done yet: Sparkle updates, a live iTerm2 run (not installed on the test Mac), and the highlight-color integration (macOS derives the highlight from the accent by default).

## Layout

```
Scene.xcodeproj           the app target Scene and the helper target scene-tweak
Sources/Scene             SwiftUI app
Sources/SceneTweak        scene-tweak helper for experimental private calls (Swift 5 mode)
Packages/SceneKit         the core as a local package, no UI
  SceneFoundation         ZIP, JSONC, safe file writes, processes
  SceneThemes             theme model, validation, library, Omarchy import
  SceneRenderers          theme files for Ghostty, iTerm2, VS Code, and Neovim
  SceneEngine             plan, apply, journal, ledger, restore, system services
  SceneIntegrations       one integration per app or system setting
  SceneSwitcher           carousel selection and shortcut rules
Config/                   Info.plist keys, entitlements, Version.xcconfig (reads version.env)
Assets/Scene.icon         app icon (Icon Composer format)
Themes/                   bundled themes (generated by Scripts/make-bundled-themes.py)
```

## Themes

A theme is a folder or a `.scenetheme` zip with `theme.json`, `wallpapers/`, and optional `apps/` overrides. Themes are data only: Scene never runs or writes theme-supplied code. Import also accepts Omarchy theme folders (colors and backgrounds only).

Bundled palettes come from Omarchy v4.0.4 (MIT), rose-pine/palette, and sainnhe/gruvbox-material. Wallpaper sources and what is known about their licenses are in `Themes/WALLPAPER_SOURCES.json`. Check image rights before distributing the app.
